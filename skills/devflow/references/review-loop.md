# 「做 / 审」循环

## 审查者怎么选

- 每轮新派一个 reviewer，不给它上一轮的讨论、作者的思路和自评：作者的解释会让审查者顺着作者的逻辑走。
- 作者和主 agent 自己审都不算独立审查。环境派不出 reviewer 时告诉用户，按用户意见处理；用户同意自审的（范围按用户说的：整个流程或某个关卡），关卡在 state.md 和汇报里记为"自审完成"，可以推进和推送，但不算审查通过，合入时按 `references/stage4-verify.md` 第 5 节由用户当场决定。
- reviewer 只出具发现，修复归作者。
- 只给它三样东西：需求/上游文档（它要对照的标准）、验收标准、产物本身（文件路径、diff、PR）。
- 告诉它这一轮重点审什么（见各阶段 reference 的审查要点），以及下面的严重度定义。
- 同一产物涉及多个维度（如代码既有逻辑又有 UI）时，可以并行派多个 reviewer，各审一个维度。

## 改动大时拆组

一个 reviewer 面对几十个文件的 diff 审得慢，也容易只看表面。源码改动（不算测试、锁文件、生成文件、快照）超过约 20 个文件或 1000 行、且能分成两组以上时，拆开并行审：

- **分组**：按逻辑单元分（验收标准编号、问题编号或模块），小单元合并，每组大致在这个规模以内。一处逻辑改动（同一函数或相邻的改动块）和它的测试放在同一组。CHANGELOG、问题清单、路由表这类各单元都往里追加的共享文件，以及锁文件、生成文件，归衔接组；其他被几组改到的文件给到每个相关组，各看自己的改动块；分组表写明每个改动块归哪组，归不了组的交衔接组。拆组后不再按维度拆；涉及 UI 时另派一个 reviewer 只看界面还原度。
- **基点**：各组的 diff 都相对同一个基点。常规和整体审查用目标分支的 merge-base（即 PR/MR 的净 diff，不含同步进来的上游改动），在已有分支上做的，在分组表里注明哪些改动是本流程之前就有的；批量修复各批的基点见 SKILL.md「批量修复」。
- **输入**：每组拿到完整的需求和验收标准，写明本组对应哪几条，产物只给本组路径相对基点的最终 diff。另派一个衔接 reviewer，给它需求（方案或问题清单）、验收标准、分组表（每组对应的条目和文件）、全部改动的文件清单和统计，具体代码按需再看；它审归给它的共享文件，并看接口和调用是否对得上、有无重复实现、合起来是否偏离需求、有无验收标准或改动文件没落到任何一组。
- **轮次**：一轮各组都审完、修完再派下一轮。有 must fix 的组、文件被别组修复改到的组进入下一轮，修复改到组间接口时衔接也进；修复新增的文件归入对应组。每轮由一个参与本轮的 reviewer 跑与改动相关的全部测试。组数超出环境能同时运行的 subagent 数时分批派。

## 严重度

要求 reviewer 给每条发现标下面三级之一，brief 里写明用这套；它自带别的分级时，按影响归入这三级：

- **must fix**：不改就不能进入下一环节——与需求或验收标准不符、正确性/安全问题、会导致返工的设计缺陷、测试造假（为通过而改测试、跳过校验、对特定样例特殊处理）、治标不治本。
- **建议**：改了更好但不影响正确性和后续工作——可读性、命名、小的简化。
- **疑问**：审查者无法确认的假设，需要作者或用户澄清。

## 停止条件

- 不设轮数上限，循环到没有 must fix 为止。"建议"由作者酌情采纳，没采纳的按「记录」记，不为建议继续循环。
- "疑问"能由作者用证据回答的就回答；涉及需求取舍的转给用户。
- 没有进展时停下复盘（自测、回归的修复循环同）：上一轮的 must fix 没真正修掉、同一问题反复出现、或修了又冒出同类问题。复盘需求理解有没有错、方案是不是从根上就不对；方向无误就继续循环，需要用户判断的，带着具体分歧找用户。新一轮 reviewer 提出新的、不同的问题，属于正常进展。

## 修复的要求

- 作者（续用原 subagent）针对每条 must fix 修复根因，逐条说明怎么改的。
- 作者不同意某条发现时，给出证据反驳；主 agent 判断谁对，拿不准就交给下一轮 reviewer 裁定。
- 下一轮可以附上上一轮的 must fix 清单，让 reviewer 确认是否真修了；不附作者的解释。

## 主 agent 在循环里做什么

- 汇总发现，校正严重度：风格问题被标成 must fix 的降级，真问题被标成建议的升级。

## 记录

轮次、结果和未采纳的建议记在 state.md；拆组或批量修复时连同基点和分组表记在工作目录的 `review.md`，state.md 只放指向；微小档没有 state.md，审查结果写进汇报。
