# 阶段 5：收尾

合入后进入收尾。用户放弃合入或中止流程时也进入收尾；PR/MR、分支和过程产物按用户意见保留。用户只是暂缓、之后还要继续时，不做清理：停止本流程启动的后台进程，并在 `state.md` 标记暂停和下一步。本阶段不改文档，文档应已在阶段 3 随 PR 提交。

## 1. 清理临时产物

先确认要保留的过程产物（证据、截图、私有备份）及其存放位置：合入时与合入确认一并询问；若事先获准直接合入、未合入或流程中止，则在本阶段询问。得到用户同意后，先将这些产物移到约定位置，再按 `state.md`「本流程创建的资源」逐项清理：

- **临时文件和目录**：只清理由本流程创建的 `/tmp`、`$TMPDIR`、会话临时目录、测试数据、截图和构建产物。
- **模拟器/模拟机**：关闭并删除本流程创建的 iOS、Android、鸿蒙等设备。本流程只启动了用户已有设备时，只关闭，不删除。
- **后台进程**：停止本流程启动的 dev server、测试服务、watcher 等。
- **工作树**：用 `git worktree remove` 删除本流程通过 `git worktree add` 创建的工作树；其中有未提交改动时先询问用户。
- **分支**：合入后删除本地和远程功能分支；仓库已自动删除的远程分支跳过。分支在工作树中检出时，先删工作树；在原仓库中检出时，先切回 `baseline.txt` 记录的分支。

完成后将当前资源与 `baseline.txt` 比较。若发现相对基线新增且未登记的资源，列给用户决定，不自行处理。

## 2. 核验并移除工作目录

先核验以下项目：

- 原仓库 `git status --short` 与 `baseline.txt` 一致。
- 已登记的进程均已停止。
- 模拟器列表中不再有本流程创建的设备。
- `git worktree list` 中不再有本流程创建的工作树。

若有差异，列出差异并询问用户，不自行处理；用户确认后视为通过。

核验通过后删除 `.devflow/<需求>/`；若 `.devflow/` 已空，一并删除。保留 `git rev-parse --git-path info/exclude` 中的 `.devflow/` 忽略规则：该文件由各 worktree 共享，规则也可能是用户原有的。

## 3. 结束汇报

用几句话向用户说明：PR 是否合入（或未合入原因）、交付内容和验收结果、清理与保留的资源及位置，以及遗留风险或后续建议。
