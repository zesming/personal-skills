# 阶段 5：收尾

合入后进入本阶段；用户决定不合入或中止流程时也走本阶段（只是暂缓的不收尾，state.md 记为暂停），PR/MR、分支和要留下的产物按用户意见保留。本阶段不改动文档（文档已在阶段 3 随 PR 提交）。

## 1. 清理临时产物

要保留的过程产物（证据、截图、私有备份）先移到用户同意的位置：合入时在合入确认里一并问，事先授权直接合入、不合入或中止时在这里问。然后按 state.md 里"本流程创建的资源"逐项清理：

- **临时文件与目录**：`/tmp`、`$TMPDIR`、会话临时目录、测试数据、截图、构建产物中由本流程创建的部分。
- **模拟器/模拟机**：关闭并删除本流程创建的 iOS 模拟器、Android 模拟器、鸿蒙模拟器等；本流程只是启动了用户原有的模拟器时，只关闭，不删除。
- **后台进程**：dev server、测试服务、watcher 等。
- **工作树**：本流程 `git worktree add` 建的用 `git worktree remove` 删除；里面有未提交改动时先问用户。
- **分支**：合入后删除本地和远程的功能分支（仓库设置已自动删除的跳过）；在工作树里检出的，先删工作树。

然后把现状与 `baseline.txt` 里的资源基线对比：相对基线新增、但没有登记的东西，列出来问用户，不擅自删除。

## 2. 核验并移除工作目录

- 核验：`git status` 干净、登记的进程已不存在、模拟器列表中已无本流程创建的设备、`git worktree list` 中已无本流程创建的工作树。
- 核验通过后删除 `.devflow/<需求>/`；`.devflow/` 为空时一并删除。保留 `git rev-parse --git-path info/exclude` 中的 `.devflow/` 忽略规则（该文件由各 worktree 共享，规则也可能是用户原有的）。

## 3. 结束汇报

用几行话向用户汇报：合入的 PR（或未合入的原因）、交付的功能与对应验收结果、清理了什么、保留了什么及位置、遗留风险或后续建议。
