# UI 与交互审查

目标：判断界面和交互是否准确、简洁、一致地表达了产品理念，用户是否能顺畅走完每条路径。

## 方法

1. **能运行就实际操作**：主 agent 已用合成数据启动本地应用时（地址在 brief 里），用环境里已有的浏览器自动化工具（Playwright、agent 自带浏览器等）逐条走核心路径，在关键步骤和问题处截图，存到 `<AUDIT>/evidence/`（brief 中给出的绝对路径）；移动端在本机已有模拟器时同理。没有启动的应用就不要自己启动，改用静态审查并说明原因。只用本地或测试环境，不用真实账号做有副作用的操作，不为此新装依赖。
2. **不能运行就静态审查**：从路由表、页面组件、样式文件、设计 token、组件库用法、文案资源推断界面结构和交互流程，在报告中注明"静态审查"。
3. **建立设计基线**：先看项目有没有设计系统、主题、组件库、文案规范；"不统一"以项目自己的基线为准，没有基线时以出现最多的那种用法为准。

## 检查要点

**是否表达产品理念**
- 首屏/首页是否让人一眼看出产品是做什么的、下一步该做什么
- 视觉重心是否落在核心功能上，次要功能是否喧宾夺主
- 信息层级：标题、主次按钮、分组是否清晰

**复杂与冗余**
- 单屏信息密度过高、同屏多个主要操作
- 同一功能有多个入口且行为不同
- 弹窗套弹窗、多级抽屉、不必要的确认步骤
- 用户必须理解内部概念才能操作

**不统一**
- 同类组件多种实现或多种样式（按钮、表单、卡片、空状态、提示）
- 颜色、字号、间距、圆角、图标风格游离于设计基线之外（如大量硬编码颜色值）
- 同一概念的文案、术语、语气前后不一；中英混用无规律
- 同类操作的位置和交互方式不一致（有的地方左上返回、有的右上关闭）

**交互走不通或不合理**
- 死路：页面无返回路径、操作后无反馈、跳转到不存在的路由、按钮无响应
- 缺状态：加载中、空数据、错误、无权限、离线时界面没有处理
- 危险操作（删除、覆盖、支付）无确认或不可撤销
- 表单：校验时机不当、错误提示不指向具体字段、提交失败丢失已填内容
- 返回/刷新后状态丢失，深链接打不开

**基础可用性**（只报明显的）
- 文本对比度明显不足、可点击区域过小
- 交互元素缺少可访问名称，键盘无法操作主要流程
- 在常见窄屏尺寸下布局破损

## 证据要求

每条问题给出截图路径或"组件文件:行号 + 复现步骤"。"不统一"类问题至少列出两处对照位置。

## 常见误报，不要报

- 纯审美偏好（"这个颜色不好看"），除非它破坏了一致性或可读性
- 设计系统中有意为之的变体
- 尚未上线、被 flag 关闭的界面，除非它会被用户看到
