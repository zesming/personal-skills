# UI 与交互审查

判断界面能否清楚表达产品意图，用户能否顺畅完成任务。界面内文案归本维度。

## 方法

1. **实际操作**：主 agent 已启动本地应用时，用现有浏览器工具或模拟器走核心路径。关键步骤和问题截图存入 `<AUDIT>/evidence/`。只用本地或测试环境，不用真实账号做有副作用的操作，不为验证安装依赖。
2. **静态审查**：应用未启动时，从路由、组件、样式和文案资源还原流程，说明采用静态审查及原因。
3. **建立设计基线**：以项目设计系统、主题、组件或文案规范为准。没有规范时，以最常见的现有做法为参照。

## 检查要点

**是否表达产品理念**
- 首屏/首页是否让人一眼看出产品是做什么的、下一步该做什么
- 视觉重心是否落在核心功能上，次要功能是否喧宾夺主
- 信息层级：标题、主次按钮、分组是否清晰

**复杂与冗余**
- 单屏信息密度过高、多个主要操作争夺焦点
- 标题、字段标签、备注、说明或空状态重复表达同一信息，且无助于理解、判断、操作或识别状态
- 同页同状态下，有多个可见入口操作同一对象并产生同一结果。指出可删哪项、保留哪个入口，以及如何验证原任务仍可完成
- 同一任务在多个入口分别维护界面或流程。比较受众、权限和信息需求，写明可共用的部分
- 嵌套弹层、重复录入和确认、可延后或合并的步骤。对照精简前后的入口、步骤和异常回路
- 用户必须理解内部概念才能操作

**不统一**
- 同类组件多种实现或多种样式（按钮、表单、卡片、空状态、提示）
- 颜色、字号、间距、圆角、图标风格游离于设计基线之外（如大量硬编码颜色值）
- 同一概念的文案、术语、语气前后不一；中英混用无规律
- 同类操作的位置和交互方式不一致（有的地方左上返回、有的右上关闭）

**交互走不通或不合理**
- 死路：页面无返回路径、操作后无反馈、跳转到不存在的路由、按钮无响应
- 缺状态：加载中、空数据、错误、无权限、离线时界面没有处理
- 危险操作（删除、覆盖、支付）无确认或不可撤销
- 表单：校验时机不当、错误提示不指向具体字段、提交失败丢失已填内容
- 返回/刷新后状态丢失，深链接打不开

**基础可用性**（只报明显的）
- 文本对比度明显不足、可点击区域过小
- 交互元素缺少可访问名称，键盘无法操作主要流程
- 在常见窄屏尺寸下布局破损

## 证据要求

每条问题给出截图路径或"组件文件:行号 + 复现步骤"。"不统一"类问题至少列出两处对照位置。

## 常见误报

- 纯审美偏好（"这个颜色不好看"），除非它破坏了一致性或可读性
- 设计系统中有意为之的变体
- 尚未上线、被 flag 关闭的界面，除非它会被用户看到
- 用户明确要求显示的内容，以及当前位置需要的错误恢复、约束说明、无障碍名称和风险提示，即使别处有类似内容
