# 图标导出与校验工作流

本文件记录可跨工程复用的工作流，不替代 [三平台官方规则](platform-rules.md)，也不规定项目目录、文件名、包名或固定导出尺寸。操作前先检查目标工程实际的配置、已批准素材、资源路径和工具链。

## 保持资产关系清晰

- 将已批准的品牌源图作为派生依据。常规导出只做符合目标格式的合成、等比缩放、编码转换和资源映射，不重画标志主体。
- 区分分层源图、包内启动器资源、启动页/关于页的单层合成图，以及商店上传图。格式或像素要求不同时，不能仅因图像内容相同就互相替代。
- 若目标支持分层图标，保留前景与背景层；需要单层图时，只从已知的图层合成。不要假定可以从一张扁平图无损还原图层。
- 不要在需要系统处理外观的资源中预先烘焙系统遮罩、圆角或阴影。确需单层图或商店图时，按目标平台现行规则生成独立变体。

## 导出与清单

1. 从目标工程识别实际配置入口和已有脚本；复用合适的项目工具，但不要把别的工程的路径、命名或脚本参数当成默认约定。
2. 按请求范围生成所需资源，并以当前官方平台规则确定尺寸、格式、透明度和色彩要求。仅修改一个平台时，不扩展到无关平台的全部导出或构建。
3. 对多目标或可重复导出，记录每个源图和导出图的用途、尺寸、色彩空间、透明度、编码格式、来源及哈希。清单用于说明派生关系，不替代对图像内容的检查。

## 校验

- 检查源图和导出图是否满足各自用途的尺寸、格式、透明度、色彩空间和文件大小要求。
- 需要合成时，检查层顺序、背景不透明性（若目标规则要求）、主体比例、裁切和像素结果；检查声明或清单是否指向预期资源。
- 只导出或转换资产时，验证导出文件和相关配置即可。修改包内资源或声明时，构建受影响的目标，并从实际产物检查资源引用、标识、编码、尺寸及像素。
- 构建工具可能重采样或转码。发现源图与包内编码不同，应结合目标 SDK/工具链版本检查转换结果；不要由包内尺寸反推所有工程的源图规则。
- 记录实际完成的检查、命令和工具版本。普通本地导出或构建不代表商店审核通过；只有用户明确要求时才执行上传、提审或发布。
